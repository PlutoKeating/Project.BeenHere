# 使用双角色纯文本采访模型

状态：Accepted<br>
最后核对：2026-09-01

## 决策

采访记录的规范草稿只包含被采访者显示信息、发生时间、来源和有序消息。消息正文只保存纯文本，角色只允许 `interviewer` 与 `participant`。标题、摘要和被采访者公开路径由系统派生，不再由录入者填写。标题只基于全部 `participant` 消息做确定性的关键词排序、语句分解与重组，采访者消息不参与标题。

录入页面当前默认接收聊天截图并在浏览器中 OCR 为双角色消息；纯文本粘贴仍作为无需模型的回退，将带“我/对方/问/答”标签的内容识别为消息，无标签的非空行按双方交替识别。两种识别结果都汇合到同一个 `RecordDraft`，必须由用户校对后保存，不自动公开。

公开版本继续保持不可变快照、编号、内容摘要和变更说明。账户所有权、认领、软删除、更正与审计模型不变。

## 结果

- 优点：2–4 条消息的采访不再要求录入 slug、标题、摘要、故事、记录说明、消息类型或话题。
- 代价：不再表达图片、停顿、章节、系统消息、故事投影与话题聚合。
- 迁移：`0002_simplify_interview_messages.sql` 只迁移双角色消息；若检测到第三角色消息或已有话题关联则失败，避免静默丢失既有内容。
- 约束：后续录入方式与实时采访都必须生成同一个精简 `RecordDraft`。
- 说明：OCR 的图片、坐标与置信度是临时输入状态，不扩展本文定义的正式消息模型；具体决策见 [ADR 0004](0004-browser-ocr-ingestion.md)。
